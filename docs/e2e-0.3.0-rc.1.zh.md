# E2E 验证记录：dsh 0.2.1-rc.2 真机（2026-10-20，0.3.0-rc.1）

> 本轮在**隔离 home**里验证 0.3.0-rc.1：24 个工具、异步控制面、审批策略的宿主写入与读取、
> 原生子代理目录。使用 `scripts/e2e-isolated.mjs` 创建临时 profile、装 link 插件、启动独立宿主
> （MCP 8095），再跑 `test/e2e.ts`；零 token 相与一次真实 turn 均通过。

## 环境

-   宿主：`@deepseek-ai/dsh@0.2.1-rc.2`（本机桌面发行版，`DeepSeek Harness.exe` 以
    `ELECTRON_RUN_AS_NODE=1` 启动 CLI）
-   隔离 home：`mkdtemp(os.tmpdir()/dsh-carrot-e2e-*)`；只复制 `.credentials.yaml` 与
    `settings.yaml.imported`，验证完保留临时目录供检查（不自动删除）
-   profile：`carrot-e2e`，`--from-default-profile web` 重建；插件经
    `dsh plugin --profile carrot-e2e add link:<已构建的临时副本>` 安装
-   MCP 端口 8095（避开常驻实例 8090 与 smoke 的 8091/8098/8099）
-   无人值守：`DSH_PERMISSION_MODE=danger-full-access`；`session_create` 显式传
    `approvalPolicy: "never"`
-   客户端：`test/e2e.ts`（零 token 相 + agent 相）

## 说明

-   本轮验证的是**审批策略的宿主读写**（`session_create.approvalPolicy` 与
    `approval_policy`）；`approvalControl` 保持默认 `off`，所以没有触发真实
    `approval/request` 的扣住/回答。扣住、回答、超时、abort、卸载等状态机由
    `test/smoke.ts` 的 143 项断言覆盖（桩宿主 + 真 MCP HTTP）。
-   本轮隔离宿主的 `pwsh` 工具成功启动；更早一次隔离运行曾因临时 cwd 的沙箱环境启动失败，
    模型总结如实写了“未产生副作用”，不影响插件工具面与 turn 收敛。
-   临时 home 与临时构建副本都保留在 `%TEMP%` 下；脚本不会自动删除，便于复查报告。
-   `scripts/e2e-isolated.mjs` 是本机开发脚本，依赖本机 DSH 发行版路径；不随包发布。
